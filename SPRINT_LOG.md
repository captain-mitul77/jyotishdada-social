# JyotishDada: Sprint Log

The live log: one row per sprint (plus follow-up rows) from Sprint 71 onward, newest first. **Sprints 1 to 70 and
their still-open follow-ups before the Sprint 102 cleanup are in `ARCHIVE.md`** (Part 1), together with the old
production tracker and backend plan. Update this log at the **end of every session**; it is the fastest way to
answer "where did we leave off?".

**How to fill a row when you finish a session:**
- `Status`: ✅ done · 🟡 partial (note what's left) · ⬜ not started
- `Date`: session date
- `Notes`: what actually got built/wired, anything that slipped to a follow-up, any deviation from the plan
- If a session covers only part of a sprint (e.g. you did endpoint #4 but wired only 2 of 3 pages), mark it 🟡 and add
  a follow-up row (e.g. `103b`) rather than marking the sprint ✅ early.
- When a follow-up is finished, remove its row and list its id in the closing sprint's Notes ("Closed by this sprint").
- If a session adds a page, section or module, document it in `PROJECT.md` in the same session, or flag it here.
- Rules for backend sprints: build the endpoint(s) and wire the matching frontend page(s) in the same session; keep
  response shapes matching the existing `lib/types.ts` types (`Panchang`, `ChartResult`, `Occurrence[]`); anything
  that cannot be verified (no network, no reference site, uncertain classical data) is said explicitly and logged as a
  follow-up, never silently guessed.

Rows below that mention `BACKEND_PLAN.md`, `PRODUCTION_TRACKER.md`, `SAMPLE_DATA_AUDIT.md`, `DEPLOYMENT_CLOUDFLARE.md`,
`SEO_FIXES_SEP2026.md` or `ADSENSE_LOW_VALUE_AUDIT_SEP2026.md` are historical: those documents were deleted in Sprint
102 (their content is in `ARCHIVE.md` where it was worth keeping).
